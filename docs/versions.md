# Versions and releases

caltrop uses `vMAJOR.MINOR.PATCH`. One number covers the script, the rules and the allowlist format. `caltrop --version` prints it.

A consumer repo's `caltrop check` fails when its hit counts go up or down, so the number says what an upgrade does to those counts.

| Part | Meaning |
|---|---|
| MAJOR | A change that breaks a consumer's `caltrop.toml` or CI setup: a rule id removed or renamed, a changed allowlist format, command, exit code or output line format, or a new required ast-grep version. Say in the release notes what a consumer must change. |
| MINOR | New rules, new languages, or a rule change that finds more or fewer hits. A consumer's counts may move: after upgrading, fix the new hits or lower the allowances. Do not re-run `caltrop baseline` to hide new hits. |
| PATCH | No hit count changes in any repo: messages, docs, tests, bug fixes in error handling, internal cleanups. A consumer can bump without touching `caltrop.toml`. |

A rule fix that removes a false positive changes counts, so it is MINOR, not PATCH.

## Where we are

Before v1.0.0, caltrop had no versions and consumers pinned a commit (vesper pins `4a6ed53`).

- **v1.0.0**: the first version. Rust rules, plus Python and TypeScript, JavaScript and Svelte. Python and TypeScript rules share allowlist ids with the Rust ones (`no-fixed-sleep`, `no-test-swap` and the rest), and two ids are new: `no-mock-libs` and `no-focused-test`. `.svelte` files are parsed as HTML, so the TypeScript rules run inside `<script lang="ts">`. pytest reruns are read from `pyproject.toml`, `pytest.ini`, `setup.cfg` and `tox.ini` anywhere in the repo. `node_modules` and `site-packages` are skipped. Adds `caltrop --version`. For Rust code the counts are the same as at `b13ef7e`; a repo pinned earlier also gets that commit's five newer Rust rules (`no-ignored-test`, `no-weak-result-assert`, `no-silent-skip`, `no-fake-impls`, and `no-test-swap` on test-only cargo features). A repo with TypeScript, JavaScript or Python files gets new hits: fix them or add allowances. Checked against food-laptop (FastAPI and SvelteKit) and vesper (whose `web/` adds about 220 TypeScript and JavaScript hits, most of them sleeps in `web/e2e/*.mjs`). Not verified: other Python or Svelte codebases.
- **v1.1.0**: new ways to install and report, and rule changes that move counts. Adds a GitHub Action (`uses: Toby-Faucher/caltrop@v1.1.0`), a pre-commit hook and a `pyproject.toml` for `pipx install`; the clone + symlink install still works. Adds `caltrop check --format github` for workflow annotations; text output is unchanged. Python: `mocker.patch.dict(os.environ, ..)`, `pytest.raises(Exception) as e` followed by a read of `e.value`, and `sleep(float("inf"))` are no longer hits; `loop.call_later(n, ..)` now counts under `no-fixed-sleep`. TypeScript: `.tsx` and `.jsx` files are now scanned (generated tsx copies of the rules, same ids); a timer that only calls `reject` is no longer a sleep; `vi.spyOn` mocked in a second step in the same block now counts under `no-mock-libs`; Svelte template logic is checked by `no-test-swap`. No rule id was removed or renamed. A repo with `.tsx`/`.jsx` tests or asyncio `call_later` gets new hits, and some Python and TypeScript allowances can be lowered: fix the new hits or lower the allowances. Checked against httpx, flask, fastapi, aiohttp, sveltejs/kit, playwright, zod and excalidraw. Not verified: vesper and food-laptop counts, and `pipx install git+..@v1.1.0` (needs the tag).
- **v1.2.0**: seven new ways a test can pass without checking anything, for Python and TypeScript, JavaScript and Svelte. New ids: `no-constant-assert` (an assertion that cannot fail, such as `expect(true).toBe(true)` or `assert x == 0 or True`), `no-source-text-test` (a test that reads a source file or `inspect.getsource` and matches its text), `no-swallowed-error` (`await p.catch(() => {})` or `except ..: pass` in a test), `no-conditional-assert` (an assertion inside an `if` with no `else`), `no-coverage-pragma` (`# pragma: no cover`, `istanbul`/`c8`/`v8 ignore`, in all code, not only tests), `no-assertion-free-test` (a test with no assertion and no call to a test helper that asserts) and `no-test-filter` (`--passWithNoTests`, pytest `addopts` with `--deselect`/`--ignore`/`-k`, Playwright top-level `testIgnore`). Existing ids find more: `no-ignored-test` counts vitest `.fails`, jest `.failing` and Playwright `test.fail`; `no-fixed-sleep` counts an empty `waitFor(() => {})`; `no-weak-result-assert` counts a TS test whose only assertions are in a `catch`, and a `pytest.raises` block with more than one statement. Rule files for one id can now have dotted variants (`no-weak-result-assert.catch-ts`); the allowlist key is still the part before the dot. No rule id was removed or renamed. Every repo with Python or TypeScript tests should expect new hits: fix them or add allowances. Checked against Toby's repos and public repos with Claude co-authored commits (barnacle, MAL, claude-orchestrator, evia-manager, dev-loops, cogmo, CnesData); measured false positives were 0% for `no-constant-assert`, `no-coverage-pragma` and `no-assertion-free-test`, and about 20% for `no-source-text-test`, `no-swallowed-error` and `no-conditional-assert`. Not verified: vesper and food-laptop counts after the bump, and most rules inside `.svelte` files. Presence-only assertions (`toBeTruthy`, `is not None`) were tried and left out at about 40% false positives.
- **v1.3.0**: `no-focused-test` counts `fit`/`fdescribe` only as a test declaration (a statement whose first argument is a string or template and whose second, if any, is an inline function), so a function under test named `fit` (`expect(fit(a, b))`) is no longer a hit; `fit.each(..)(..)` and `fdescribe.each(..)(..)` now are. `caltrop check` exits 2 when ast-grep runs fewer rules than caltrop ships (for example when a `.gitignore` above an install hides `rules/`), instead of passing with no hits. CI runs `caltrop check` on caltrop's own repo. A repo with a function named `fit` in its tests should lower those `no-focused-test` allowances; no other counts move. Checked against vesper (12 false hits gone, nothing else changed) and brisk, cloudberry, food, vigil, earshot, hush, pika and lemonate (no change). Not verified: a real focused `fit` in a real repo (none in the corpus; rule-tests only), and a real pre-commit install hitting the new exit 2.
- **v1.4.0**: rules from a line-by-line read of an AI-written FastAPI + SvelteKit test suite. New ids: `no-stubbed-gate` (a FastAPI `dependency_overrides` entry that only raises 401/403, in a test that then asserts that status, or a user-named fixture that overrides an admin gate) and `no-mock-subject` (a TS test file that `vi.mock`s the module it is named after; it replaces the `no-mock-libs` hit on that call). Existing ids find more: `no-mock-libs` counts a Python test that assigns to an attribute of an imported module and never undoes it (`sqlalchemy.ARRAY = ..`); `no-fake-impls` counts a class whose base is named like a fake, a method-bearing class defined inside a test, and classes named for the failure they fake (`Flaky*`, `*Crash*`, `Always*`); `no-weak-result-assert` counts a status check that lets a 5xx through (`status_code in (400, 500)`, `>= 400`, `!= 200`), a TS sentinel `throw` caught by its own `catch`, and bare `pytest.raises(SystemExit)`/`IntegrityError`/`DatabaseError`; `no-constant-assert` counts `all(.. if ..)` over a filter and an always-true array predicate. `no-mock-libs` finds fewer: `vi.mock` of SvelteKit's `$env/*`, `$app/env*` and `$app/navigation|stores|state|forms|environment|paths`, and `monkeypatch.setattr` of an ALL_CAPS name to a literal, are no longer hits. No id removed or renamed. A SvelteKit repo should lower its `no-mock-libs` allowances; a Python repo with module-level SQLAlchemy shims in tests gets new `no-mock-libs` hits (allowlist them or move them into a fixture that undoes them). Checked against Toby's repos (vesper gains 2 `no-fake-impls` hits, brisk is unchanged), a private FastAPI + SvelteKit codebase, and public repos (fastapi, flask, requests, httpx, celery, typer, immich, marimo, polar and others): the measured false-positive rate was 0 for most changes, about 8% for the assignment check (celery) and 1 in about 60 for the wider fake check. Not verified: the sentinel and `no-stubbed-gate` shapes in any public repo (none had them), and `no-mock-subject` with path aliases other than `$lib`, `@` and `~`.
- **v1.5.0**: fixes from a team's first run on their FastAPI + SvelteKit repo. caltrop skips generated files: any file whose first 5 lines contain `@generated`, `DO NOT EDIT` or `generated by`/`from`/`using` (OpenAPI and protobuf clients). `no-source-text-test` no longer counts source read to be parsed (`ast.parse`, libcst `parse_module`, `ts.createSourceFile`, babel/acorn/svelte `parse`), in the same call or through a variable in the same block: a structural guard checks shape, not text. No id added, removed or renamed. Counts only go down: lower the allowances for generated files and parse-based guards. Not verified against that repo's files.
- **v1.6.0**: from a team's first full run on their FastAPI + SvelteKit repo. Text output is grouped: a per-rule summary first, then each rule's message once over its hits, each printed as `path:line: rule-id` (no trailing colon and message, so a script that greps the old `path:line: rule-id: message` form needs updating; `--format github` is unchanged). New: `no-stubbed-gate.always-allow-ts` (a TS test that mocks a permission check such as `can` or `hasRole` to always return `true`; it replaces the `no-mock-libs` hit on that call) and `no-constant-assert.or-substring-py`/`-ts` (`"x" in s or "no" in s`, where one side is empty, one character or a stopword); `no-deadline-poll.unbounded-py` gives a `while` loop with no bound a message saying it hangs CI (same base id). Fewer hits: Python `no-mock-libs` skips `mocker.spy`, replacements that call the original they replace, `pytest.fail`/`AssertionError` tripwires and ALL_CAPS constants set to any value; `no-fixed-sleep` skips a sleep in a stand-in (a method of a non-test class, or a nested def the test hands to the code under test); `no-coverage-pragma` skips test code and pragmas on `raise AssertionError`/`assert False`; `no-fake-impls` skips a failure-named subclass of a real class whose methods only raise, wait or call `super()`, and a class assigned to `window.X`/`globalThis.X`; `no-weak-result-assert` skips a status list without 500, `raises(Exception) as e` followed by a check of `e.type`/`e.match`, and a `with` block that ends in the test's own `raise`. No id removed or renamed; counts mostly go down, so lower allowances, and TS repos may gain `no-stubbed-gate`. Checked on Toby's repos, a private FastAPI + SvelteKit codebase and public repos (pytest, pip, aiohttp, starlette, outline, immich, zulip, bits-ui). Not verified on the team's repo, and the TS sleep exemption was left out (it hid real e2e sleeps).

## How a release is cut

1. Work lands on `main` by pull request. CI must be green. Nothing is merged to `main` without a pull request.
2. Open a pull request named `Release vX.Y.Z` from a `release/X.Y.Z` branch, with one commit `chore(release): vX.Y.Z`. It sets `VERSION` in the `caltrop` script and adds the version's line under "Where we are" above, with what changes for consumers and what was not verified. Pick the number from the table above. Run the tests in the README first.
3. After it is merged, tag the merge commit: `git tag -a vX.Y.Z -m "caltrop vX.Y.Z" && git push origin vX.Y.Z`.
4. Create the GitHub release from the tag: `gh release create vX.Y.Z --generate-notes`. The notes are the merged pull requests. There is no CHANGELOG file.
5. Bump the consumers (vesper) to the tag in their own pull requests, and fix or allow the new hits there.
